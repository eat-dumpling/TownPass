## 給開發 Agent 的說明

這份文件是回收小里長的開發規格。請依「開發清單」的順序實作，每完成一項就對照它的完成標準；規格沒寫到的地方，選最簡單、文字最少的做法。

### 目標

在台北通 WebView 中做出一個可以完整 Demo 的兒童微服務：掃描或選圖 → 收服 → 建設 → 清運關卡 → 今晚任務 → 家長確認。Demo 限時 2 分鐘。

### 一定要遵守

- AI 只在手機上： CLIP 在 WebView 內推論，不呼叫任何雲端 API，不用生成式 AI。
- 分類只來自規則表： 模型只負責「認出是哪個品項」，怎麼分一律查 items.json。
- 介面清楚好玩： 依「介面與視覺規範」：圖像優先、每個畫面一個主角、對孩子有吸引力。
- 授權： 套件只用 MIT、BSD、Apache-2.0；地圖用開源方案。
- 隱私： 不收集兒童個資；相機畫面不上傳、不存檔；位置用完即丟。
- 來源： 每個資料來源、模型與生圖工具都寫進 README。

### 不要做

- 帳號系統、排行榜、聊天、後端資料庫（P2 的匿名統計除外）。
- 垃圾車即時位置：沒有這份資料，只用排定時間。
- 介面上的說明段落與文字教學。

### 交付物

web/（Vue 前端）、scripts/（建置腳本）、data/（品項與題庫）、townpass/（台北通修改）、測試、README.md。

### 完成的定義

開發清單的 P0 全部勾完、測試通過；在 Android 實機的台北通中跑完 Demo 腳本；開飛航模式時掃描仍可使用。

## 產品概述

回收小里長是台北通裡給兒童的養成遊戲：孩子用手機掃一掃要丟的真實垃圾，分對了就拿到回收資源，用來建設自己住的那個里，再把學會的帶回家實際做到。辨識用手機上的 CLIP 模型，不確定時改問一題線索；分類依臺北市環保局規則；作業研究負責推理、資源取捨與清運路線。不使用生成式 AI。

### 三句話

1. 功能鏈： 孩子用手機掃一掃要丟的真實垃圾，手機上的模型認出它、不確定時再問一題看圖就能答的線索，分類依臺北市環保局規則；分對了就拿到回收資源，用來建設自己住的那個里，再用定位找到家門口那班垃圾車、排出它的最佳清運路線，今晚實際幫家裡把回收拿下樓。
2. 效果： 孩子不用背規則，在收集、建設、守護的循環裡自然學會分類，還把環保變成每天在家實際做的事；遇到看不懂中文的新住民父母，孩子也能用爸媽的母語教他們，全家一起分對。
3. 巧思： 模型認不出來時不亂猜，而是變成偵探線索，由作業研究挑出最關鍵的一題；建設和守護時它化身「回收工廠」和「清運大作戰」兩個關卡，讓孩子在臺北市的真實地圖與真實垃圾車班次上，玩出資源取捨和準時清運的道理。

### 目標族群

| 族群 | 角色 | 需要什麼 |
|---|---|---|
| 約 5–8 歲兒童 | 主要玩家 | 全圖像、語音、只分一般垃圾、回收、廚餘三桶 |
| 約 9–12 歲兒童 | 主要玩家 | 更細的回收分類、回收工廠與清運大作戰 |
| 家長（含新住民父母） | 確認者、被教的人 | 用自己的語言看任務卡、確認孩子真的完成 |

### 和「看不懂」主題的對應

| 主辦方向 | 做法 |
|---|---|
| 多語服務 | 家長版任務卡與小老師題目有英文、印尼文、越南文 |
| 易讀設計 | 孩子不讀規則，只回答看圖就能答的問題 |
| 圖像化指引 | 每種垃圾是一隻垃圾怪，每個桶有固定顏色與圖示 |
| 分齡介面 | 兩個年齡段用不同的分類粗細與關卡難度 |

## 分析

現有工具只回答「這個要丟哪」，而且都是給大人用的查詢網頁；回收小里長要解決的是「孩子想不想學、學了會不會做」。差異在三件事：可累積的養成、臺北的真實地圖與清運資料、作業研究做成的關卡。

### 痛點

- 規則對孩子太抽象： 立體類、平面類、分天收運都是大人的用語。
- 家裡不一定有人會： 新住民家庭的父母常看不懂中文規則；2026 年廚餘又改成新制。
- 背了也不會做： 學校教過分類，但孩子很少參與家裡實際的倒垃圾。

### 往屆作品與競品

| 工具 | 做什麼 | 和回收小里長的差異 |
|---|---|---|
| townpass2024-recycling（2024 第二名） | 拍照後送雲端 GPT-4o 判斷大類、垃圾車地圖 | 不用 AI，依規則推理；對象是兒童；有養成與真實任務 |
| townpass2025-stampquest（2025 第三名） | NFC 打卡集章、任務與徽章 | 不需要硬體；任務來自家裡的真實垃圾與清運時間 |
| townpass2025-carbon-notebook（2025 第二名） | 發票算碳排、地球心情遊戲化 | 獎勵綁在孩子親手完成的行動，需家長確認 |
| 回收一點通（環保局） | 約 1,032 個品項的分類查詢 | 要先知道品名；是我們規則表的來源 |
| 垃圾清運路線查詢（環保局） | 路線與附近點位 | 給大人查；我們用同一份資料做成關卡與任務 |

### 優勢

- 不用生成式 AI： CLIP 只從固定的品項清單挑選，分類一律依規則表，結果可追溯到環保局規則；模型不確定時改問線索，不亂猜。
- 臺北味十足： 地圖是孩子真實的里，清運關卡用家門口那班垃圾車的真實停靠點與時間。
- OR 是玩得到的： 兩個關卡本身就是最佳化問題，評審一眼看出技術在哪。
- 不是刷題： 進度會累積成看得到的里。
- 落地單純： App 端只需允許 WebView 使用相機、新增一個排程通知 Handler。

### 劣勢

- 品項有限： 模型只能從品項清單挑選，涵蓋規劃好的常見品項（MVP 約 60 種）。
- 線索要孩子自己回答： 答錯線索就會推錯；對策是每題都是看圖就能答的二選一。
- 無法驗證孩子真的丟了： 靠家長確認，並限制每天的次數。
- 遊戲平衡需要調整： 資源、建築與星等都是遊戲設定，24 小時內只能粗調。

### 風險與機會

- 機會： 學校環境教育可以直接使用；市府可以看到哪些品項最常被分錯。
- 風險： 規則寫錯會教錯孩子；每條規則都要有來源與「已核對」標記。
- 風險： 兒童隱私與位置資訊一定會被問；設計上只存里的名稱，不存位置。

## 真實垃圾回饋

量用「袋」來算，不用「件」：孩子不需要每丟一件就掃一次。掃描只用在還不會分的東西，學會之後就不用再掃；真正的回饋來自每次倒垃圾時按下的「倒了幾袋」。臺北本來就是一般垃圾隨袋徵收，袋是最自然的單位。

### 三種行為，三種回饋

| 行為 | 什麼時候 | 記錄什麼 | 回饋 |
|---|---|---|---|
| 掃一掃或選圖 | 遇到還不會分的東西 | 學會了哪些品項 | 新垃圾怪、資源 |
| 我要丟（快速回報） | 每次丟已學會的東西，一鍵 | 丟了哪個品項 | 動畫、知識句、任務進度、偶爾考考你 |
| 今晚要倒嗎？ | 收運日傍晚一次 | 今晚要帶哪幾袋 | 今晚任務 |
| 倒完了 | 倒完後，家長確認 | 實際倒了幾袋、一般垃圾用哪種尺寸的專用袋 | 金色資源、本週報告 |

### 學會了就不用再掃

- 同一品項分對 3 次（門檻是遊戲設定）就標成「學會了」，圖鑑卡變金色，並移到「常丟清單」，之後一鍵回報就好。
- 學會的品項再掃不給資源，只會說「你已經會了！」。
- 「考考你」會定期複習學會的品項；答錯就暫時移回「還在學」。
- 學會的品項可以拿來在小老師模式考爸媽。

### 量怎麼算

- 一般垃圾： 依專用垃圾袋規格算公升（3L 到 120L 共七種，每公升 0.36 元），可以直接換算成袋子花費，例如 14L 袋每個約 5 元。
- 回收與廚餘： 只記袋數與「小、中、大」，不換算重量。
- 沒倒的日子不用記： 不會因為沒打開 App 而算錯。
- 標明是估計： 這是家庭自己回報的數字，報告上要寫清楚。

### 本週家庭報告

| 指標 | 怎麼算 | 畫面 |
|---|---|---|
| 一般垃圾 | 本週專用袋的總公升與花費，和上週比 | 少 1 袋，省 5 元 |
| 回收袋數 | 本週倒了幾袋回收 | 一個數字 |
| 準時倒 | 完成的今晚任務次數 | 徽章 |
| 新學會 | 本週新學會的品項 | 金色圖鑑卡 |
| 分對率 | 第一次就放對桶的比例 | 星星 |

- 臺北市 2024 年回收率 70.8% 是全市、以重量計算，和家庭袋數的口徑不同；只放在城市知識卡，不在報告裡比較。
- 報告只存在手機上；P2 才考慮匿名上傳全市統計。

### 不能變成「丟越多越好」

- 獎勵看新學會、準時倒、一般垃圾變少；袋數本身不給獎勵。
- 學會的品項再掃不給資源；每天收服有上限。
- 「倒完了」要家長確認。

## 遊戲化：每次丟垃圾都有回饋

孩子每丟一次垃圾，10 秒內就能得到回饋、複習一點知識，並推進任務與成就。獎勵一律看行為（分對、學會、準時、減量），不看丟了多少。

### 每次丟垃圾的流程

1. 按「我要丟」： 首頁最大的按鈕。
2. 選或掃： 學會的東西在「常丟清單」，一鍵選；沒學過的就掃一掃。
3. 拖進桶： 做對立刻有動畫與音效；做錯只晃一下，給一句提示。
4. 一句「它會去哪裡」： 例如一般垃圾「會被送到焚化廠」；句子來自 facts.json，每句都有來源。
5. 任務進度跳一格。 每 5 次快速回報出一題「考考你」，複習已學會的品項；越久沒複習的品項越先出（間隔重複）。

快速回報不需要家長確認，所以只給少量經驗值、每天有上限；資源只來自新學會與完成任務。

### 回饋分三層

| 層 | 時機 | 孩子看到什麼 |
|---|---|---|
| 立即 | 每次丟 | 動畫、音效、一句「它會去哪裡」、任務進度 |
| 當天 | 傍晚與倒完 | 今晚任務、家長確認、金色資源、連續天數 +1 |
| 長期 | 每週與累積 | 成就徽章、等級、里的新建築、本週報告 |

### 任務

每天給 3 個任務：一個學習、一個行動（只在收運日）、一個探索。學習任務挑孩子最弱的類別。

| 類型 | 例子 | 怎麼確認 | 獎勵 |
|---|---|---|---|
| 每日學習 | 學會 1 個新垃圾怪；考考你答對 2 題 | App 自動判定 | 資源 |
| 每日行動 | 今晚把回收帶下樓 | 家長確認 | 金色資源 |
| 每日探索 | 清運大作戰過一關；蓋一個建築 | App 自動判定 | 經驗值 |
| 每週減量 | 自備水壺或環保杯 3 次；買東西少拿一個塑膠袋 | 家長確認 | 特別建築 |
| 故事任務 | 「小里長的第一週」：依序學會回收、廚餘、一般垃圾 | App 自動判定 | 解鎖里的新區域 |

### 成就

門檻都是遊戲設定，可調整。

| 成就 | 條件 | 等級 |
|---|---|---|
| 分類學徒／達人／大師 | 學會 5／20／60 個品項 | 銅、銀、金 |
| 準時小尖兵 | 準時倒 3／10／30 次 | 銅、銀、金 |
| 連續守護 | 連續 3／7／21 個收運日有回報 | 銅、銀、金 |
| 減量英雄 | 一般垃圾連續 2／4 週不比上週多 | 銀、金 |
| 稀有怪獵人 | 收服 5 種稀有怪 | 金 |
| 廚餘新制通 | 學會所有廚餘相關品項 | 金 |
| 小老師 | 考爸媽 5 次，而且爸媽答對 | 金 |
| 清運指揮官 | 清運大作戰 5 關三顆星 | 金 |

### 等級與連續天數

- 經驗值： 學會新品項、答對考考你、完成任務都有，每天有上限。
- 小里長等級 1–10： 每升一級解鎖一種建築或吉祥物裝扮。
- 連續天數只算收運日： 週三、週日停收，不會讓連續中斷。
- 中斷不懲罰： 只顯示「明天再一起努力」。

### 「它會去哪裡」知識句

- 每個類別一組短句，存在 facts.json，每句附來源連結；沒有來源的句子不上線。
- 例：一般垃圾「會被送到北投、內湖或木柵焚化廠」，來源是焚化廠營運管理報告。
- 一句最多 12 個字，搭一張圖與語音。

### 設計守則

- 不鼓勵製造垃圾： 丟的件數與袋數都不給獎勵。
- 不比較、不羞辱： 沒有排名，做錯只給提示。
- 真實行動要家長確認： 今晚任務與減量任務。
- 每天有時間上限： 到了就提醒孩子去做真實任務。

### 資料結構

```json
{ "id": "daily_learn_new", "type": "daily_learning", "goal": { "event": "item_learned", "count": 1 }, "reward": { "resource": 2 }, "verify": "auto" }
{ "id": "weekly_own_cup", "type": "weekly_reduce", "goal": { "event": "own_cup", "count": 3 }, "reward": { "building": "water_station" }, "verify": "parent" }
{ "id": "on_time_scout", "type": "achievement", "tiers": [3, 10, 30], "event": "disposal_confirmed" }
```

所有任務與成就都由事件驅動：item_learned、item_logged、quiz_correct、disposal_confirmed、building_built、route_cleared、own_cup 等。前端用一個事件匯流排更新進度，新增任務只要改 JSON。

## 介面與視覺規範

畫面要讓孩子一眼看懂、想一直玩：以插圖與角色為主，文字是輔助。每個畫面只有一個主角，其他東西退到旁邊。本節的規則優先於其他章節裡的示意文字。

### 視覺原則

| 原則 | 做法 |
|---|---|
| 圖像優先 | 每個畫面有一張大插圖或角色；按鈕都是「圖示＋短字」 |
| 一個主角 | 每個畫面只有一個最大的可點東西，例如首頁的「我要丟」 |
| 角色帶路 | 吉祥物小里長出現在每個畫面，用表情與一句話回應孩子 |
| 會動才好玩 | 做對：怪物跳進桶、星星飛到任務條；做錯：桶子搖頭；動畫 1 秒內結束 |
| 顏色有意義 | 每個類別一個固定顏色與桶子造型，從圖鑑到今晚任務都一樣 |
| 步驟用圖 | 倒空、沖洗、壓扁、撕膜、包好、貼膠帶都有固定圖示，排成小漫畫 |
| 危險要醒目 | 危險或特殊品項用警示色外框與「要大人幫忙」標籤 |
| 大而好按 | 按鈕與圖卡要大，適合小手；數值依台北通設計規範與無障礙指引 |
| 有聲音 | 每句字都有語音；5–8 歲自動播放 |

> （圖示／示意 widget：見線上文件 .31129）

三個畫面各示範一個原則：首頁只有「我要丟」最大、送回家用圖示排出步驟、分類指南用警示外框標出要大人幫忙的品項。美術以此版面為骨架，換上插圖與角色。

### 文字規則

| 項目 | 建議 |
|---|---|
| 標題 | 短句，像角色在說話 |
| 按鈕 | 圖示加 2–4 個字 |
| 線索題 | 一句問句，用兩張大圖回答 |
| 怪物台詞 | 一句，有個性，例如「我不住這裡喔」 |
| 9–12 歲 | 可以多一行說明原因，內容要有來源 |
| 避免 | 長段落；5–8 歲模式不出現「立體類」等專有名詞 |

### 生圖流程

1. 寫清單： prompts/assets.csv，每行一個檔名與主體描述，例如 monster_bubble_tea_cup：a plastic bubble tea cup character with a sealed film lid。
2. 批次生成： 用 Codex CLI 的生圖功能，主體描述加上風格提示詞。實際指令與額度依你們安裝的版本確認。

## 完整分類指南

App 內建一本「分類指南」：一般、回收、廚餘之外，把容易搞錯與危險的品項整理成「特殊」分頁。每一筆都依環保局「回收一點通」與官方公告整理並附來源；官方說法互相衝突的品項先不上線。指南就是圖鑑，學會的卡變金色。

### 指南怎麼組織

- 四個分頁： 回收（含平面類、立體類）、廚餘、一般垃圾、特殊（電池、燈管、危險品與要預約的）。
- 每張品項卡： 大插圖、處理步驟圖示、「交到哪裡」圖示、安全標籤、來源。
- 找品項： 掃一掃或點圖；9–12 歲可以打字搜尋。
- 涵蓋範圍： MVP 先做約 60 種常見品項加上本節的難分類品項。「回收一點通」全站已整理成 1,031 筆，可作為之後擴充的來源；它不是開放資料平台上的資料集，使用時要註明出處。

## 功能一「收服」：掃一掃，認出垃圾怎麼分

孩子對準要丟的東西掃一掃，手機上的 CLIP 認出它是哪個品項，再依臺北規則表判斷怎麼分。模型不確定時，OR① 挑最關鍵的一題線索；認不出來或不想開相機，就改用大圖卡。孩子親手把垃圾怪拖進正確的桶，才算收服。

### 玩法流程

1. 掃一掃： 對準要丟的東西，按一下。
2. 認得出來： 前幾名候選都屬於同一個臺北類別，垃圾怪直接現身。
3. 不確定： 前幾名分屬不同類別，怪物問一題線索，例如「是紙做的嗎？」。
4. 認不出來或不用相機： 改選 6 張大圖卡之一，再回答 0 到 3 題線索。
5. 送它回家： 把垃圾怪拖進桶子。做對就收服；做錯怪物說「我不住這裡喔」，可以再試一次。
6. 拿到獎勵： 垃圾怪加入圖鑑，依材質拿到回收資源。

線索問完仍分不出來（答了「不知道」或超過 3 題），改成從 2–3 張圖卡裡直接選。

### CLIP 掃描（裝置端）

| 項目 | 規格 |
|---|---|
| 模型 | OpenAI CLIP ViT-B/32 的 Transformers.js 版（Xenova/clip-vit-base-patch32），只用影像模型的量化版，約 89 MB；第一次使用時下載並快取 |
| 授權 | OpenAI CLIP 原始碼為 MIT；使用前到模型頁確認權重授權 |
| 標籤 | 每個品項 3–5 句英文描述；文字向量在建置時算好，存成 text_embeds.json，手機上不跑文字模型 |
| 推論 | 瞄準框裁切 → 影像向量 → 與每個品項算 cosine → softmax → 前 5 名與機率 |
| 判定 | 前 5 名同一類別且累計機率過門檻 → 直接現身；分屬不同類別 → 交給 OR①；最高機率太低 → 大圖卡。門檻與 softmax 溫度用測試照片調整 |
| 執行環境 | Transformers.js（Apache-2.0），有 WebGPU 用 WebGPU，否則用 WASM |
| 效能目標 | Demo 手機上單次辨識約 1–2 秒；這是目標值，要先實測 |
| 備案 | 太慢就在開發階段用 CLIP 幫圖片標註，蒸餾成約 5 MB 的 MobileNetV3-Small |
| 測試 | 30 件臺灣常見物品照片，記錄品項第一名、前三名與臺北類別正確率，寫進 README |
| 相機 | 台北通預設不允許 WebView 開相機，要改 App（見系統架構）；畫面只在記憶體中處理，不上傳、不存檔 |
| 規則揭露 | README 寫明模型名稱、版本、量化格式、推論框架與來源 |

不要用：Apple MobileCLIP（權重授權看起來限研究用途）、Chinese-CLIP（大陸廠牌，規則禁止）。

### 品項與規則資料

MVP 涵蓋約 60 種臺北家裡常見的垃圾，由資料組對照「回收一點通」與環保局分類規則整理。每個品項有一組看圖就能答的屬性，與一個臺北類別：

### OR①：最少提問決策樹

問題： 候選集合 S 是掃描的前 5 名，或選完大圖卡後的品項。每題 q 會依屬性把 S 分成「是」「否」兩群。目標是用最少的期望題數，確定「臺北類別與處理步驟」，不需要確定是哪一個品項。

```latex
V(S) = \begin{cases} 0 & \text{if every item in } S \text{ shares one category and steps} \\ \min_{q} \left( 1 + \sum_{a \in \{\text{yes},\text{no}\}} P(a \mid S, q)\, V(S_{q,a}) \right) & \text{otherwise} \end{cases}
```

- P(a | S, q)： 掃描路徑用 CLIP 的機率；大圖卡路徑用品項的常見程度（資料組標 1–3）。
- 掃描路徑即時求解： 候選只有 5 個，手機上直接用動態規劃算，幾乎不花時間。
- 大圖卡路徑預先算好： 每張大圖卡約 10–15 個品項、約 12 題，開發時用 Python 算出最佳決策樹，輸出 trees.json。
- 限制： 最多 3 題；「不知道」直接改成圖卡選擇。
- 給評審看的數字： 測試照片的平均提問數，對比「每題都問一次」的固定問卷。

## 功能二「建設」：用資源把自己的里變漂亮

地圖是孩子真實住的里，孩子用「收服」得到的資源在上面蓋建築，里會越來越綠。資源有限，所以要自己決定先蓋什麼；回收工廠用整數規劃算出最佳組合，給星等與提示。

### 玩法流程

1. 第一次使用： 家長選行政區與里，或用一次定位自動判斷。只存里的名稱。
2. 看到自己的里： 地圖上顯示里的邊界，裡面有數個「空地」。空地是遊戲位置，不代表真實土地。
3. 進回收工廠： 看自己有多少塑膠晶片、紙纖維、金屬塊、堆肥，選要蓋的建築。
4. 拿星星： 孩子的組合越接近最佳解，星星越多；卡關時可以請「工廠長」給提示。
5. 蓋下去： 把建築拖到空地，里的綠意值上升，畫面變得更漂亮。

### 建築設計

資源配方與綠意值都是遊戲設定，畫面上要標明，不當作真實的回收比例。範例：

```json
[
  { "id": "bench",     "name": "公園長椅", "cost": { "plastic": 3, "metal": 1 }, "green": 4 },
  { "id": "tree",      "name": "遮蔭樹",   "cost": { "compost": 3 },             "green": 5 },
  { "id": "library",   "name": "小圖書角", "cost": { "paper": 4, "metal": 1 },   "green": 6 },
  { "id": "playground","name": "遊樂設施", "cost": { "plastic": 4, "metal": 2 }, "green": 8 },
  { "id": "garden",    "name": "堆肥花園", "cost": { "compost": 2, "paper": 1 }, "green": 4 }
]
```

- 每種建築卡附一句「回收物可以變成新東西」的知識；如果要寫真實數字，必須附來源。
- 9–12 歲模式開放更多建築與更緊的資源，工廠關卡也更有挑戰。

### OR②：回收工廠（整數規劃）

問題： 用現有資源與空地數，決定每種建築蓋幾個，讓里的綠意值最高；多蓋不同種類有加分，鼓勵多樣性。

```latex
\max \; \sum_j g_j x_j + \sum_j b\, y_j \quad \text{s.t.} \quad \sum_j a_{ij} x_j \le R_i \;\; \forall i, \quad \sum_j x_j \le N, \quad x_j \le N y_j, \quad x_j \in \mathbb{Z}_{\ge 0}, \; y_j \in \{0, 1\}
```

- x 是建築數量、y 表示該種建築有沒有蓋、g 是綠意值、a 是配方、R 是現有資源、N 是空地數、b 是多樣性加分。
- 規模： 建築種類 5–8 個、空地十幾個，用分支定界法在手機上即時求得最佳解，不需要後端。
- 星等： 孩子的綠意值 ÷ 最佳綠意值；門檻是遊戲設定，例如達 95% 給三顆星。
- 提示： 工廠長不直接給答案，先說「你的紙纖維還沒用完」這類線索，第二次才顯示最佳組合。
- 孩子學到的： 資源有限要取捨；分對類的垃圾才能變成新東西。

### 里的地圖

- 資料： 臺北市里界圖，12 個行政區、456 個里，座標系統為 TWD97，2026-01-06 更新。下載格式待確認；若不是 GeoJSON，可改用臺北市 ArcGIS 服務的 geoJSON 查詢。
- 前處理： 開發階段用腳本把 TWD97 轉成 WGS84 經緯度（proj4），簡化邊界線，依行政區輸出 12 個小檔。
- 空地： 在里的邊界內均勻取 12–20 個點，每個里的空地位置固定，全家看到的一樣。
- 顯示： Leaflet 加 OpenStreetMap 底圖；底圖以淡色呈現，重點是里的邊界與建築。
- 判斷住哪個里： 可用 turf.js 做點在多邊形內的判斷，之後立刻丟掉座標。

### 城市知識卡

- 一般垃圾去哪裡： 臺北有北投、內湖、木柵三座焚化廠，各廠的營運管理報告是開放資料，每年更新。
- 臺北的回收率： 2024 年 70.8%，來自垃圾清運處理狀況。
- 知識卡在蓋完建築或完成任務時出現，一次一張，不要讓孩子讀長文。

### 開發

| 項目 | 做法 |
|---|---|
| 里界前處理 | build_li.py：座標轉換、簡化、產生空地點、依行政區輸出 |
| 前端元件 | LiMap（Leaflet）、SlotLayer、FactoryPanel、BuildingCard、KnowledgeCard |
| 求解器 | factory.js：小型分支定界法；單元測試與暴力列舉結果比對 |
| 遊戲平衡 | buildings.json 由企劃調整；請一位隊友實際玩 10 分鐘調配方 |

完成標準： 任一里都能載入地圖與空地；工廠最佳解與暴力列舉一致；建築與綠意值會存在手機上。

## 功能三「守護」：指揮垃圾車，今晚真的去倒

守護把臺北市垃圾車點位路線資料和定位結合起來：系統用定位找到會經過你家附近的那一班垃圾車。遊戲裡，孩子用這班車真實的停靠點排最佳路線；現實裡，系統告訴你今晚幾點、在哪裡倒，錯過了還能追到哪一站。

### 用定位找到你家的那班垃圾車

1. 取得位置： 家長同意後，用台北通內建的定位取得一次位置，只在手機上計算。
2. 找附近的停靠點： 從全市 4,012 個停靠點找出步行範圍內的點，依距離排序。步行範圍是可調的設定。
3. 還原每一班車： 把資料依「路線＋車次」分組、依抵達時間排序，就得到這班車依序會停的所有點。
4. 決定「我家的那班車」： 經過你家附近、時間最適合你家的那一班，以及它最靠近你家的停靠點。
5. 只存編號： 手機上只存「路線、車次、停靠點」的編號，座標立刻丟棄。

不想用定位的家庭，可以在地圖上直接點選家附近的停靠點。停靠時間是清潔隊的排定時間，不是垃圾車的即時位置，畫面上要標明。

### 清運大作戰（遊戲）

玩法：

1. 地圖上出現「你家那班垃圾車」真實會停的 8–10 個點，取自它經過你家附近的那一段路線。每個點旁邊有時間窗，例如「16:30–16:40」。
2. 孩子依序點選停靠點，畫面上的垃圾車跟著走，時鐘往前跑。
3. 在時間窗內到達的點變綠色，太晚的點變紅色，居民會說「垃圾車怎麼還沒來？」。
4. 全部綠色才過關，路程越短星星越多。
5. 過關後顯示三條路線：孩子的、最佳解、清潔隊真實的排程；再播放「今晚這班車會這樣走」的動畫，最後停在你家附近那一站。

資料： 臺北市垃圾車點位路線資訊，全市 4,012 筆，欄位含行政區、里別、分隊、車號、路線、車次、抵達與離開時間、地點、經緯度。用「路線＋車次」與抵達時間，就能還原每班車的停靠順序。資料沒有「星期幾」欄位，先以環保局公告的週三、週日停收推定。一班車會不會跨多個里、每班有幾個點，要在開發時實際算一次。

### OR③：帶時間窗的路線最佳化

問題： 一台垃圾車從出發點出發，每個停靠點都要在它的時間窗內到達（提早到可以等），求總路程最短的順序：

```latex
\min \sum_{(i,j)} d_{ij}\, x_{ij} \quad \text{s.t.} \quad e_i \le t_i \le l_i, \quad t_j \ge t_i + s_i + \tau_{ij} - M (1 - x_{ij}), \quad \text{each stop visited once}
```

- d 是兩點距離（由經緯度算直線距離）、τ 是行駛時間（距離 ÷ 遊戲車速）、s 是停留時間、[e, l] 是時間窗。
- 關卡怎麼取點： 從你家那班車的停靠順序裡，取你家附近前後連續的 8–10 個點；難度越高，點越多、時間窗越窄。
- 求解： 最多 10–12 個點，用帶時間的 Held–Karp 動態規劃精確求解，手機上可以算完。
- 真實排程一定可行： 清潔隊的順序本身就符合時間窗，可當作基準；最佳解距離若更短，是因為遊戲用直線距離，不代表清潔隊排錯，畫面要說明。
- 遊戲化調整： 真實時間窗大多只有幾分鐘，關卡可以等比例放寬，並標明「遊戲時間」。
- 孩子學到的： 為什麼垃圾車要準時、為什麼錯過就要再等，也就是臺北「垃圾不落地」的制度。

### 今晚尖兵任務（現實）

玩法：

1. 系統依「我家的那班車」與今天星期幾，知道它今晚幾點到你家附近。
2. 傍晚派一件任務：「21:05 巷口（步行約 3 分鐘），幫媽媽帶回收這袋。」
3. 停靠時間前收到通知。
4. 錯過了就追車： 按「我沒趕上」，系統再定位一次，從這班車接下來的停靠點裡，找出「走過去還來得及」、而且走最少路的那一站：「垃圾車 21:15 會到中山北路口，走過去約 4 分鐘。」
5. 都追不上，或是週三、週日，就改指向最近的限時收受點。
6. 完成後家長按確認，孩子拿到金色資源，可以蓋特別的建築。

追車怎麼算： 對這班車接下來的每一站 k，步行時間 w 由直線距離乘上繞路係數、除以步行速度估算（係數與速度是可調的假設），從來得及的站裡選步行最短的：

```latex
k^{*} = \arg\min_{k} \; w_k \quad \text{s.t.} \quad t_{\text{now}} + w_k \le l_k
```

l 是垃圾車離開該站的排定時間。計算全在手機上進行，位置用完就丟。

任務規則：

| 條件 | 規則 |
|---|---|
| 今天有沒有收 | 週三、週日停收，當天沒有任務 |
| 派什麼類別 | 依傍晚「今晚要倒嗎？」選的袋子派任務，並優先派當天的分天類別：週二、四、六立體類，週一、五平面類 |
| 孩子能不能做 | 只派孩子已經在收服中分對過的類別 |
| 安全 | 不派廚餘、玻璃、電池、燈管；任務卡提醒「請和大人一起下樓」 |
| 次數 | 一天最多一件 |

### 家長確認與多語

- 家長關卡： 確認任務、改設定、切換語言前，要先回答一題簡單的大人題。
- 家長版任務卡： 英文、印尼文、越南文，孩子版仍是中文。
- 小老師： 孩子從自己的圖鑑挑 3 個垃圾怪考爸媽；爸媽看到的題目是他們的語言。爸媽答對，全家一起升級。
- 翻譯： 開發階段產生、人工審核後存成固定 JSON，不在執行時翻譯。

### 技術棧選擇與理由

選擇原則：台北通官方已有的優先、開源寬鬆授權、能離線在手機上跑、套件越少越好。每個套件使用前都要再確認 LICENSE。

| 層 | 選擇 | 為什麼 | 沒選的替代方案 |
|---|---|---|---|
| 前端框架 | Vue 3 + Vite + TypeScript | 台北通官方範例採用 Vue 3，且已把 postMessage 封裝成 composables（useConnectionMessage、useHandleConnectionData），可直接沿用 | React：可行，但要自己重寫溝通層 |
| 狀態管理 | Pinia | Vue 官方狀態管理，管資源、圖鑑、進度 | Vuex：已不建議新專案使用 |
| 本機儲存 | IndexedDB（idb-keyval） | WebView 內可持久保存，容量比 localStorage 大，可存模型快取 | localStorage：容量太小 |
| 多語 | vue-i18n | Vue 的標準做法，每種語言一個 JSON | 自寫字典 |
| 影像辨識 | CLIP ViT-B/32 量化版 + Transformers.js | 零樣本、不用訓練資料，直接對應臺北品項清單；全在手機上 | MobileCLIP：權重授權限研究；Chinese-CLIP：大陸廠牌；自訓模型：要大量照片 |
| 地圖 | Leaflet + OpenStreetMap | 指引要求開源地圖；點、線、多邊形就夠用，設定最少 | MapLibre：要向量圖磚；Google Maps：不符規則 |
| 地理計算 | turf.js（執行時）、pyproj、shapely（建置時） | 點在多邊形內、距離；座標轉換與邊界簡化 | — |
| 求解器 | 自寫 TypeScript：分支定界、Held–Karp、動態規劃 | 問題規模小，自寫最輕、可離線、好解釋、好測試 | OR-Tools：要後端或大型 WASM，對這個規模太重 |
| 建置腳本 | Python 3 | 資料處理與決策樹預算最方便 | — |
| 拖拉與動畫 | Pointer Events + CSS 動畫 | 不用額外套件，手機觸控最穩 | 拖拉套件 |
| 測試 | Vitest | 與 Vite 原生整合 | Jest |
| 部署 | Firebase Hosting | 指引建議的前端部署方式 | — |
| App 端 | 台北通 fork（Flutter） | 只改相機權限與一個 Handler | — |

地圖圖磚： OpenStreetMap 官方圖磚有使用政策，Demo 可用；正式上線要改用市府或自架的圖磚。

### 台北通整合

| 功能 | 內建或自加 | 用途與做法 |
|---|---|---|
| location | 內建 | 找你家的那班車、追車、判斷住哪個里 |
| notify | 內建 | 立即通知（排程通知的備案） |
| open_link | 內建 | 打開環保局「回收一點通」等來源頁 |
| WebView 相機 | 要改 App | 台北通開啟微服務的 TPWebView 沒有處理權限請求；要傳入 onPermissionRequest 允許相機，iOS 開啟 inline 播放並更新相機用途說明 |
| photo_capture | 自加，備案 | 相機權限做不到時，用已安裝的 image_picker 拍一張照片回傳 |
| schedule_notify | 自加 | 今晚停靠前提醒；另加 cancel_notify 取消 |

網頁端要先判斷 window.flutterObject 是否存在；在一般瀏覽器開發時用模擬的 flutterObject 回傳假資料。

schedule_notify 訊息格式：

```json
{ "name": "schedule_notify", "data": { "id": 1107, "title": "今晚的尖兵任務", "content": "21:05 巷口，帶回收這袋", "at": "2026-11-07T20:55:00+08:00" } }
```

Flutter 端： 依台北通的 TPWebMessageHandler 介面新增一個類別，用已安裝的 flutter_local_notifications 排程：

```dart
class ScheduleNotifyMessageHandler extends TPWebMessageHandler {
  @override
  String get name => 'schedule_notify';

  @override
  Future<void> handle({
    required Object? message,
    required WebUri? sourceOrigin,
    required bool isMainFrame,
    required Function(WebMessage replyWebMessage)? onReply,
  }) async {
    if (message is! Map<String, dynamic>) {
      onReply?.call(replyWebMessage(data: false));
      return;
    }
    // 解析 id、title、content、at，以 zonedSchedule 排程
    onReply?.call(replyWebMessage(data: true));
  }
}
```

- 需要加入 timezone 套件設定臺北時區，並加進 App 的 Handler 清單。
- Android 13 以上要請求通知權限；精準鬧鐘權限可不申請，幾分鐘的誤差可以接受。
- 另加 cancel_notify 讓任務完成時取消提醒。

### 資料管線

1. 下載： 垃圾車點位（data.taipei API）、限時收受點、里界圖。
2. 轉換： 里界 TWD97 轉 WGS84；「1630」轉成分鐘數；依「路線＋車次」排出停靠順序。
3. 切檔： 依行政區輸出，只下載使用者需要的那一區。
4. 品項與決策樹： items.csv 轉成 items.json，再算出 trees.json。
5. 檢查： 自動測試：每個品項都能在 3 題內判定；每班車的真實排程都是可行解；每個里都有空地。
6. 更新： 點位資料是不定期更新，上線後每週重跑一次建置即可。

## 兒童安全、隱私與規則遵循

服務不收集兒童個資，相機畫面不上傳也不存檔，位置用完即丟，所有進度都存在手機上。唯一的 AI 是在手機上執行的 CLIP，符合競賽「AI 推論須於裝置端完成」的規定。

### 兒童安全

- 不需要兒童帳號： 使用家長的台北通；孩子只有一個暱稱與頭像。
- 家長關卡： 設定、任務確認、語言切換都要先通過大人題。
- 沒有廣告、沒有和陌生人的排名、沒有聊天功能。
- 每天遊戲時間有上限： 由家長設定；到了就提醒孩子去做真實任務。
- 現實任務的安全： 只派安全類別，任務卡寫明「請和大人一起下樓」。
- 不監督他人： 「尖兵」只協助自己家，沒有檢舉別人分錯的功能。

### 隱私

| 資料 | 處理方式 |
|---|---|
| 住在哪個里 | 家長手動選，或定位一次後只存里的代碼，座標立刻丟棄 |
| 常去的停靠點 | 存在手機，只是公開資料裡的一個點位編號 |
| 圖鑑、資源、建築 | 存在手機（IndexedDB），不上傳 |
| 照片 | 相機畫面只在記憶體中辨識，不上傳、不存檔 |
| 市府統計（P2） | 只收匿名的品項分錯次數，不收任何個人或位置資料 |

### 競賽規則遵循

- AI： 執行時只有 CLIP 在手機上辨識，不呼叫雲端、不用生成式 AI；README 揭露模型名稱、版本、量化格式、推論框架與來源。開發階段用 Codex CLI 產生美術、用雲端 AI 產生語音或翻譯時，依規定在 README 寫明模型、用途與人工審核方式。
- 資料： 核心資料全部是官方開放資料（政府資料開放授權條款第 1 版），README 與 Demo 標示資料集名稱與連結；地圖標示 OpenStreetMap 出處。
- 授權： 作品以 AGPL 開源；套件選 MIT、BSD、Apache-2.0，例如 Vue、Leaflet、proj4js、turf.js，使用前確認 LICENSE。
- 地圖： 使用開源方案，不用 Google Maps。
- 內容正確： 每條分類規則都有來源與「已核對」標記，未核對的不展示。
